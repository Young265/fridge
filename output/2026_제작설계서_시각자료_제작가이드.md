# 2026 제작설계서 시각자료 제작 가이드

프로젝트: **독거노인의 식생활 관리를 위한 AI 기반 스마트 냉장고**

## 1. 최종 편집 원칙

- 설문조사 결과서와 인터뷰 결과서는 실제 조사를 수행하지 않았으므로 **완전히 제외**한다.
- 최종 문서는 원본 36쪽에서 원본 5~6쪽을 삭제한 **34쪽**으로 구성한다.
- 원본 1~4쪽은 번호를 유지하고, 원본 7~36쪽은 최종본에서 2쪽씩 앞으로 이동한다.
- 좌상단 파란 제목 탭, 우상단 한이음드림업 로고, 가는 파란 선, 연청색 표 헤더를 유지한다.
- 원본의 빨간 `샘플 1/2`와 하단 `본문의 예시 내용을...` 문구는 최종본에서 삭제한다.
- 사용자가 제작할 그림은 SVG를 우선하고, PNG라면 가로 1,600px 이상으로 만든다.
- 도형 안 문장은 2줄 이내, 화살표는 교차하지 않게 하고, 선 두께와 색상을 모든 그림에서 통일한다.
- 색상 권장: H/W·센서=주황, AI=보라, 서버·DB=파랑, 앱·사용자=초록, 예외·경고=빨강.

## 3. 그림별 제작 방법

### 최종 7쪽 - 유즈케이스 정의서

- 왼쪽 40%에 시스템 경계 사각형을 그리고 제목을 `AI 스마트 냉장고 시스템`으로 쓴다.
- 왼쪽 Actor는 `사용자`, 오른쪽 Actor는 `Raspberry Pi`, `백엔드 서버`로 둔다.
- 시스템 내부 타원: `로그인`, `냉장고 선택`, `재고 확인`, `재고 수정`, `레시피 확인`, `식재료 촬영`, `AI 인식`, `재고 저장`.
- 사용자 연결: 로그인·냉장고 선택·재고 확인/수정·레시피 확인.
- Raspberry Pi 연결: 식재료 촬영·AI 인식·재고 저장.
- 백엔드 연결: 재고 저장·레시피 추천.
- 오른쪽 60% 표에는 개요, 주/보조 Actor, 우선순위, 선행조건, 후행조건, 기본·대안 시나리오를 적는다.

### 최종 8~9쪽 - 서비스 구성도

- 핵심 연결: `리드스위치·카메라 → Raspberry Pi 5 → YOLO 탐지·식재료 분류 → Flask API → MySQL → Flutter 앱`.

- 8쪽은 사용자 행동 중심으로 `문 열림 → 촬영 → 인식 → 저장 → 앱 확인`을 5단계 그림으로 만든다.
- 9쪽은 시스템 중심으로 위 구성요소를 좌→우 블록으로 만들고, 아래에 각 컴포넌트 역할을 1~2줄로 쓴다.
- 향후 보호자 알림은 현재 미구현이므로 우측 끝에 점선 `향후 확장` 박스로만 표시한다.
- 권장 파일명: `08_service_scenario.svg`, `09_service_architecture.svg`.

### 최종 10쪽 - 서비스 흐름도

- 위→아래 순서: `문 열림 감지 → 카메라 촬영 → YOLO 후보 추출 → contour 보완 → 분류 → confidence 판정 → stable frame 판정 → /upload → DB 저장 → 앱 표시`.
- 판단 도형은 마름모로 만든다.
- `confidence 미달`은 `재촬영/확인 필요`, `stable frame 미달`은 촬영 단계로 되돌린다.
- 문 닫힘 소비 흐름은 오른쪽 보조 분기로 `문 닫힘 → /consume → 수량 1 감소 → 0이면 삭제`로 그린다.

- 중앙에 `Raspberry Pi 5`, 주변에 `카메라`, `리드스위치`, `자석`, `전원`, `백엔드 서버`를 둔다.

### 최종 19쪽 - ERD

- 테이블: `users`, `fridges`, `fridge_items`, `ingredients`, `recipes`, `recipe_ingredients`, `app_state`.
- 중앙에 `fridge_items`, 왼쪽에 `users → fridges`, 오른쪽에 `ingredients`, 아래에 `recipes ↔ recipe_ingredients`를 둔다.
- 모든 엔티티에 PK/FK를 명시하고 Crow's Foot 관계선을 사용한다.
- 핵심 관계: users 1:N fridges, fridges 1:N fridge_items, ingredients 1:N fridge_items, recipes N:M ingredients.

### 최종 22~23쪽 - 알고리즘 명세·상세 설명

- 후보 추출 우선순위: `YOLO 박스 → contour 후보 추가 → 후보 없음 시 center fallback`.
- 이후 `crop padding → trusted detector label 여부 → 전용 분류기 → confidence ≥ 0.65 → 동일 signature 3회 → cooldown 확인 → 업로드`.
- 마름모 분기에는 Yes/No를 표시한다.
- 22쪽은 왼쪽 흐름도, 오른쪽 단계별 설명을 같은 번호로 맞춘다.
- 23쪽 상단에는 목적/입력/출력/임계값을 표로 쓰고, 하단에는 `정상 인식`과 `오인식/낮은 confidence` 결과 이미지를 좌우 비교한다.

### 최종 31쪽 - H/W 기능 실사

1. 전체 장착: 냉장고, 카메라, 리드스위치, Pi, 케이블 경로.
